# Message-to-Ticket Normalization

> Sprint 6 — How external messages become ticket candidates.

## Normalization Pipeline

When an intake request passes validation and trust checks, it is normalized into a standard ticket candidate format before admission.

### Input Shape

```python
{
    "title": "Fix terrain rendering",       # Required
    "worker": "unity-worker",               # Required, must be in ALLOWED_WORKERS
    "description": "Terrain has z-fighting", # Optional
    "branch": "feature/fix-terrain",         # Optional
    "priority": "high",                      # Optional (defaults to "normal")
}
```

### Normalization Steps

1. **Title sanitization**: Truncated to 200 chars, null bytes removed, control chars stripped, whitespace trimmed
2. **Description sanitization**: Same rules, 2000 char limit
3. **Branch sanitization**: Same rules, 256 char limit
4. **Priority validation**: Must be one of `low`, `normal`, `high`, `critical` — invalid values default to `normal`
5. **Metadata attachment**: `intake_source` and `normalized_at` timestamp added

### Output Shape

```python
{
    "title": "Fix terrain rendering",
    "worker": "unity-worker",
    "branch": "feature/fix-terrain",
    "priority": "high",
    "description": "Terrain has z-fighting",
    "intake_source": "local_simulated",
    "normalized_at": "2024-01-15T10:30:00Z",
}
```

## Ticket Candidate Format

Admitted tickets are written as Markdown files in `tickets/inbox/`:

```markdown
---
id: intake-20240115103000-a1b2c3d4e5f6g7h8
title: Fix terrain rendering
worker: unity-worker
branch: feature/fix-terrain
priority: high
intake_source: local_simulated
---

Terrain has z-fighting
```

## Forbidden Fields

These fields are rejected if present in intake payloads:
- `id` — Generated by the system, not the caller
- `_path` — Internal field, potential path injection
- `_body` — Internal field

## Content Safety

All string fields are checked against unsafe patterns:
- Path traversal (`../`)
- Shell metacharacters (`` ` ``, `$`)
- Script injection (`<script>`)
- Command injection (`; rm`, `; exec`, etc.)

Any match causes immediate rejection with audit record.

## Length Limits

| Field | Max Length |
|---|---|
| Title | 200 characters |
| Description | 2000 characters |
| Branch | 256 characters |
| Other fields | 500 characters |
